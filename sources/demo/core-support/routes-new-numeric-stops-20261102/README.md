# Route stop numeric form support

The new-route editor serialized nonempty estimated-dwell and arrival-radius inputs as JSON strings. `PendingStopDto` expects nullable integers, so the server rejected that payload and returned the form with an empty client-side stop list. This support patch converts those two values to numbers and preserves blanks as null. It does not change the user's original Core checkout.

`before/` and `after/` contain the exact reviewed static script. `source-identities.json` binds both hashes. `test-payload.mjs` executes the real Add Stop and submit handlers, reproduces the original string payload, and checks numbers, zero, null and the existing required-field guards. Run `node test-payload.mjs` from this directory.

For an isolated recording stack only, run `python3 apply-runtime.py --stack-name resgrid-academy-oct25` for a read-only preflight. Add `--execute` to copy the reviewed static file after saving the original under ignored `sources/demo/private/`. It refuses an unexpected runtime hash. The web application keeps its read-only `/app` mount: a short-lived, networkless helper updates only this file in the verified named web-publish volume. The helper uses an already-installed image and never pulls one. Reload the ordinary New Route page afterwards; existing unsaved client stops are not recovered. It neither restarts the application nor changes database data or routing-provider settings.

The patch is also retained for review in a disposable compatible Core checkout. No staging, commits or pushes are part of this process. A rebuilt container needs the patch applied again unless its source already contains the correction. In the recorded successful UI run, the route returned as Draft with two stops. The reopened editor retained both rows, and the Directions summary retained their 10/15 minute dwell times, contacts and notes. A separate read-only persistence check verified the inherited/75 m radii. Stop-order changes also survived fresh page loads. This verifies form saving; the Directions page still reports that driving directions could not be retrieved. No successful road routing is inferred.
