Open Shifts and find the Calendar section. Add Static Shift creates a dated coverage window for selected units. Use this when you need a fixed commitment, such as a community standby, a security detail or a search support period. The calendar in this exercise is November. Select Add Static Shift to open the form. Use a separate training unit while you learn the save and update process.

Give the shift a recognizable Name. The example uses Verified static coverage. Choose a light Color so the calendar’s black text stays readable; the help beside the field calls this out. Add a Description explaining the work and any coordination instructions. This fictional description also reminds the editor to verify dates and retained units before updating. A clear title and description help people recognize the commitment when they open it from the calendar.

Set Start Date and Time to November twelfth at nine in the morning, and End Date and Time to five that afternoon. The start help describes when entities are committed; the end help describes when they are available again. Under Units, select the fictional static demo unit and confirm its selected tag. Check both dates and the chosen unit before Create Static Shift. Dismiss the date picker so it does not cover the unit selection or save control.

Select Create Static Shift, then open the matching event from the calendar. View Static Shift Day shows November twelfth at nine, the shift title and description, and the selected unit. This is the saved result, not the preparation form. The training unit has no configured unit-role slots, so this example does not claim that any person has been assigned. Compare the saved day and unit with the intended commitment before moving on.

Select Edit Static Shift. The reopened dates retain nine in the morning through five in the afternoon. Read the yellow warning before Update: editing clears the shift’s assignments or signups and rebuilds them from the new settings. In this version, the Units selection is initially empty on Edit. Deliberately select every unit you intend to retain. Coordinate the change before updating a staffed operational shift; do not assume a saved date change preserves existing signups.

For this disposable exercise, move the window to November thirteenth, ten in the morning through six in the evening. Reselect the same training unit and verify its tag. Review the warning and select Update once. Open the saved calendar event again. Its day detail now shows November thirteenth at ten, with the same unit still listed. That readback checks both the new date and the unit submitted with the update.

Reopen Edit to check the persisted start and end values: ten A M and six P M on November thirteenth. The Units picker is empty again in this editor, even though the saved day detail just showed the unit. Do not submit another update while merely reviewing. Select Cancel to leave the stored shift unchanged. Use the saved day detail to verify the current unit commitment, and review the edit warning whenever a change is actually required.

Use this same create, verify and carefully update process for search and rescue, security companies, wildland contractors and industrial emergency teams. Community paramedicine, mental health response, fire and E M S teams can plan fixed support windows as well. Choose a meaningful unit and coverage period, keep calendar labels readable, and verify the saved result after every change. This lesson covers a fixed unit commitment; recurring rotations and personnel signup workflows have their own walkthroughs.
