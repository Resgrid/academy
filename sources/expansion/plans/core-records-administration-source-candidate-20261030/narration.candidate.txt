Department administrators use record definitions to give authors a consistent form and lifecycle. In Records, open Manage and choose Definitions. This example builds a department-owned form for a fictional community coordination exercise. The catalog separates published and draft versions. A definition describes the form; an individual record stores one completed entry. Choose New definition for the new exercise, leaving the product-owned forms unchanged.

Start from template is set to Blank definition. Give Definition a unique lower-case key, then enter the Name and Category. Here the name is Training Only, Community Software Exercise, and the category is Academy Software Exercises. The key cannot be changed after creation, so review it before choosing Create definition. The returned editor identifies version one as Draft and confirms that the definition was created. It is not yet a published form.

Lifecycle preset is QuickEntry, supporting a draft followed by finalization. Records per call is Multiple per call. Require author attestation at finalize is checked; reviewer and approver roles are not selected for this example. Under Numbering, Sequence width is four and Assign number is OnFinalize. Reset yearly is checked, while the station and incident sequence options are off. These choices provide one annual sequence for this definition and issue the number when the record is finalized, rather than when its draft first appears.

Classification is Standard. In Client surfaces, only Responder is selected. Allow offline is off, Allow attachments is on, and Keep photo coordinates on attachments is off. These settings express this version’s choices; they do not demonstrate a successful field-app submission. The Fields table describes the unchanged starter form: Summary is required ShortText, while Notes is optional LongText. A short summary helps identify an entry; longer notes provide its context. Check that table rather than mistaking the nearby JSON example for the saved form.

At the foot of the reopened draft, Validate, Save draft and Review impact and publish are separate controls. Validate checks the definition without publishing it. The retained validation result says The definition is valid, while the version remains Draft. The save confirmation says Draft saved. That confirms a definition save, not an individual record entry. Freshly reopening the saved version retains its numbering and attestation settings. Keep the validation result, saved configuration and publication state distinct.

Review impact and publish opens Publish impact. Before the first publication, Published version is a dash and Breaking change is No. Read the impact before making the version available. Client readiness compares app availability, client surfaces and capability. Only Responder is offered this version. Publish is the publication control; the table itself is neither publication confirmation nor a demonstration of using the form in that app.

After the approved publication, the resumed version already shows Published and read-only. Open new draft is available for later changes; another Publish is not needed for this version. History identifies the current published version and its publication date. Its saved numbering and author-attestation choices remain visible. The complete settings view also retains Standard, the client and attachment choices, and the Summary and Notes fields. This is the configuration authors will use.

The published department form identifies its name and version one, QuickEntry, above Summary and Notes. Confirm that identity before typing; a generic Training form would be a different record type. The lower form offers Save draft and Save and finalize. We start without a file or attestation. Enter a distinct exercise Summary and explain its purpose in Notes. Here the text describes software practice and makes no claim of a visit, care, attendance or operational action. Choose Save draft first so the saved entry can be checked before finalization.

The returned record is Draft, with reference D, E, K, C, M, S and no final record number. Author and Owner are Wallace Boden. Station and group resolves to Command, although the new form showed None. Read the saved result rather than assuming that a blank selection remained blank. Keep this reference so later editing and attachment work stay with the same record.

Use Edit on this draft instead of opening another New Record form. Update Notes to explain that the summary and public handout were reviewed in the fictional exercise. Read the complete statement in the editor, then use Save draft. A fresh readback of the same reference contains those revised Notes and remains Draft. The separate readback is the check that the intended text was retained.

On the saved record, Attachments provides Choose Files, File classification and Add attachment. Choose the public software handout and select Unrestricted operational content, then use Add attachment. This choice is for that file; it is separate from the form’s Standard classification. The fresh list contains academy-record-exercise dot text, two hundred forty-two bytes. The next-upload selector has reset to Restricted. That reset does not describe the file already stored; check its retained metadata in the finalized revision.

Read the saved Summary and Notes before checking the accuracy attestation and choosing Finalize. The statement applies to the entry’s actual contents; it does not turn a software exercise into physical work or attendance. The fresh result shows Finalized and the issued number T R N A D M, Twenty Twenty-Six, Zero Zero Zero One. The draft reference remains alongside it. Amend is available for a later correction to a finalized record.

History now shows revision one, Finalized, with the author and date. The handout remains listed. Use View on that history row. The resulting HTML revision identifies the same record. Its attachment metadata retains the filename, byte size, checksum and Unrestricted classification. The checksum matches the public handout. This is the stored classification, independent of the reset upload selector. Farther down, Values preserves the saved Summary and Notes alongside the draft reference and record number. Review this specific revision when checking what finalization retained.

Back in Records, the new custom row is Finalized. The three earlier records remain present: an Amended Training entry, a Work Draft and the older Finalized Training entry. Read Record number, Type, State and Summary together to choose the intended row. This record-entry sequence created only its own custom entry; finding it again does not require creating a replacement.

For later use, return to the definition catalog. The department-owned row shows published version one, no draft version, and its own New Record control. Use that row to select the intended form. The actual launcher opens the named version-one form with Summary and Notes. This later check leaves the new form empty. Returning to the queue still shows four records, with no second custom draft.

Fire and EMS teams can use a small form for exercise briefings. Community-care and mental-health teams can standardize coordination notes with suitable information rules. Search-and-rescue teams can organize mission-preparation summaries. Security teams can structure patrol briefings, wildland coordinators can prepare seasonal orientation forms, and industrial teams can retain system-training notes and a public handout. Across those settings, choose fields, numbering and client access for the task.
